발딛기 시간·착지 위치 후보 검토

2026-11-10 · 기준 a453370 · 검토용 후보 / 커밋 없음

기준 실행 파일은 해당 커밋에 읽기 전용 계측만 추가한 빌드다. 후보는 작업 트리의 변경 사항을 빌드했다. 두 실행 파일의 SHA-256과 변경 파일별 해시는 아래 버전 명세에 보존했다.

기본 적용을 권장하지 않는 후보다. 목표 궤적의 속도·가속도 제한과 역진자 모델의 회복 평가를 구현했지만, 실제 캐릭터에서는 기존에 버티던 고속·대각 충격에서 회귀가 발생했다. 기본값은 기존 고정 시간 방식으로 유지했다. 후보는 발딛기 UI의 실험: 시간·착지 위치 회복 평가에서 켤 수 있다. 구현 완료로 확정하지 않았다.

수정한 흐름과 판단 규칙

  1. 실제 COM 위치·속도, 양쪽 고관절·다리 길이, 발바닥 크기와 접촉 상태를 입력한다.
  2. 후보 시간은 고정 물리 틱의 정수배로 0.15–0.4초 사이에서 탐색한다. 각 시간에 35개 시작 후보를 만들고 속도·가속도·보폭·교차·다리 도달 범위의 교집합으로 투영한 뒤 모든 조건을 재검사한다. 다리 도달 범위는 궤적의 8개 시점에서도 검사한다.
  3. 고정 높이 역진자의 ω=√(g/h), 캡처 포인트 ξ=c+v/ω를 사용한다. 지지점 p 아래의 미래 상태는 c(t)=p+(c−p)cosh(ωt)+v·sinh(ωt)/ω로 예측한다. 모델은 발바닥 안에서 압력중심을 조절할 수 있다고 가정한다.
  4. 착지 후 기존 하중 확인 시간 0.05초 동안은 기존 지지점을 유지한다고 예측한다. 새 지지영역에서 남는 캡처 오차를 계산하고, 반대 발로 한 번 더 딛는 경우에도 도달 제약을 적용해 오차를 비교한다. 서로 다른 시간의 오차는 exp(−ωt)를 곱해 현재 시각으로 환산한다.
  5. 현재보다 모델 오차가 2mm 이상 줄어드는 후보 중, 오차 감소량 / 첫 지지 확보 시간이 큰 후보를 고른다. 이 목적함수와 유한 후보 탐색은 프로젝트용 설계이며 인용 논문의 알고리즘을 그대로 구현한 것이 아니다.
  6. 선택한 시작점·착지점·시간·높이를 한 걸음 동안 고정한다. 실제 접촉 후 기존 하중 확인을 거쳐 다시 계획한다. B 이탈 유예 0.2초, 접촉·낙상 판정과 관절 제어는 변경하지 않았다.

수평 목표의 최대 속도 1.5D/T, 최대 가속도 6D/T²를 제한한다. 수직 목표는 높이 차이와 들기 곡선의 상한을 더해 보수적으로 검사한다. 초기 제한값은 수평 2m/s·30m/s², 수직 1m/s·40m/s²이며, 실제 다리의 검증된 성능값으로 확정한 수치는 아니다. 계획 시간이 끝난 뒤 기존 착지 추가 하강 제어는 별도다.

Khadiv 등의 시간·위치 동시 조정 연구, Smaldone 등의 실행 가능성 기반 시간 조정 연구를 설계 방향의 근거로 사용했다. 그 연구의 안정성 보장을 이 래그돌에 그대로 적용할 수는 없다.

실제 캐릭터 비교

동일 모델·PA·Idle·초기 배치·고정 dt=1/60초·720틱(12초)을 사용했다. 정면·측면·대각은 키네마틱 플레이어가 2초 대기 후 기존 이동 입력으로 접근한다. 고속 조건은 기존 시나리오 5의 액티브 플레이어에 120틱에서 15m/s 속도 입력을 추가한다. 이후 입력 시퀀스도 기준/후보에서 같다. 후보 실행은 -footstepadaptive 1로 명시했다.

저장된 실제 B 배율은 2.86, 몸통 충돌 질량 8kg, 반지름 배율 1.15, 높이 배율 1.14였다. PA와 애니메이션 경로 및 SHA-256은 버전·애셋 명세에 있다. 수치는 기준 → 후보 순서다. ‘지지 해제 없음’은 12초 관찰 범위에 한정한다.

낮아진 IK 오차를 회복 개선으로 해석하면 안 된다. 후보가 더 빨리 넘어지면 유효 IK 측정 구간도 짧아진다. IK 지표는 2–12초 중 지지가 해제되지 않았고 유효한 IK 요청이 있는 샘플만 사용했다. 전체 관찰 결과와 샘플 수를 함께 봐야 한다. 접지 중 발 중심 속도에는 발 구름·회전도 포함되며 접촉점의 순수 미끄러짐 측정은 아니다.

측면 조건은 입력 시작 2초보다 먼저 지지가 해제되어, 깨끗한 정지 상태에서의 충격 회복 비교로 해석할 수 없다. 이 실패도 원본 기록에 남겼다. 별도의 강제 액티브 Idle 12초 시험은 기존 모드와 후보 모드 모두 지지 해제·불필요한 발딛기 없이 유지됐다.

정면 조건 4.0초의 실제 렌더링

정면 조건의 3초 장면에서 후보 더미는 상체가 앞으로 기울고 골반이 내려간 자세다. 4초 장면에서는 후보 더미가 바닥에 누워 있으며, 기준 더미는 아직 서 있다. 기준도 4.133초에 지지를 잃으므로 이를 최종 회복 성공으로 해석하지 않는다. 화면은 실제 DX12 렌더 타깃을 읽은 정지 장면이며 카메라는 캐릭터를 따라 이동한다. 영상 전체를 본 것으로 보고하지 않았다. 떨림 주파수와 접촉점 미끄러짐은 직접 계측하지 않았다.

검증 결과와 남은 문제

  • Debug x64 ModelViewer 빌드 성공. PhysicsWorldTests 실행 성공: 발딛기 882개 검사, IK 273개 검사 및 기존 물리 시간·접촉·StandingSupport 검사.
  • 새 검사는 55개 COM 속도 상태, 계획 고정, 출력 속도·가속도, 실제 착지 확인, 후속 스텝 평가, 이미 들린 발의 더 긴 실행 시간, 유효하지 않은 입력·도달 불가·지지 해제 거절을 포함한다. 속도 격자에서 20개 상태가 시작했고 그중 16개가 후속 스텝 평가를 사용했다. 다른 상태는 시작하지 않았으며 회복 성공으로 집계하지 않았다.
  • 기준 커밋의 원본 단위 테스트도 독립적으로 재현했다. B 바깥에서 즉시 중단을 기대하는 기존 검사가 실패했다. 후보 테스트는 기존 런타임의 유예 정책에 맞춰 ‘기하학적 이탈만으로 중단하지 않음’과 ‘명시적 유예 만료 후 중단’을 구분했다. 원본 실패 로그를 보존했다.
  • 실제 충격 기록의 PASS는 유한 상태·기록 완료·PhysX 오류 없음이라는 뜻이다. 자세 복구 성공을 의미하지 않는다. 특히 고속·대각 조건의 회귀가 남아 있어 후보를 기본 사용하도록 승인할 근거가 부족하다.
  • 기준 RagdollArticulation.cpp에는 보상 토크 clamp가 이미 주석 처리돼 있고 PD 최대 토크가 PX_MAX_F32인 실험 코드가 있었다. 이번 변경에서 토크 상한을 풀거나 수정하지 않았다. 유한 토크 상한에서의 포화 검증, 제한 전 요구량·실제 적용량·포화 지속 시간은 완료하지 못했다. 기존 무제한 상태의 결과를 포화 검증으로 대체하지 않는다.
  • 상수 높이·발바닥 내 압력중심 조절·예측한 지지 교대가 실제 관절/접촉 제어와 일치한다는 보장이 없다. 현재 몸의 각운동량, 지속 외력, 실제 골반 낮추기, 관절별 토크와 각도 제약을 동역학 모델에 포함하지 않았다. 8개 시점의 길이 검사는 연속 궤적 전체의 전신 도달 증명이 아니다.
  • 후속 발을 거절하는 원인과 실제 지지 교대 지연을 더 계측하고, 실제 관절 성능·유한 토크 기준으로 모델을 보완해야 한다. 기준 시간·토크·B 판정을 완화해서 성공으로 만들지 않았다.
