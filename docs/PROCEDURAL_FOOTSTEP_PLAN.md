# 절차적 발딛기 및 다리 IK 적용 계획

상태: 첫 Idle 더미 대상의 시작 조건과 착지 목표 계산 규칙을 확정했다. 실제 발딛기를 검증할 수 있도록 발 이동 궤적·다리 IK·관절 목표 연결까지 구현 범위를 확장한다. 새로 포함한 궤적·IK의 세부 설계는 아래 초안에서 구체화한다. 실행 코드 구현·시뮬레이션 검증은 아직 하지 않았다.

## 1. 범위

- 발딛기 시작 조건 설정.
- 착지 목표 위치 계산.
- 발을 들어 목표까지 이동시키고 내려놓는 궤적 생성.
- 발 위치·방향 목표를 다리 IK로 본 목표 자세에 반영하고, 기존 관절 드라이브로 실제 발딛기 수행.
- 실제 착지 확인, 다음 발딛기 재평가, B 이탈 시 보정 중단까지 연결한 Idle 더미 검증.
- 이번 작업은 계획 문서 작성이며, 실행 코드 구현은 아직 시작하지 않는다.
- 장기 요구: 걷기·달리기 애니메이션을 계속 진행하면서 충격에 대응할 수 있어야 한다.

## 2. 합의된 내용

### 첫 검증은 Idle 더미부터 진행

걷기·달리기로 확장할 수 있게 설계하되, 첫 구현·검증은 Idle 더미가 충격으로 밀리는 상황을 대상으로 한다. 이후 걷기·달리기의 발 타이밍과 연결한다.

### 발딛기 필요성은 COM 예측을 기준으로 판단

현재 COM이 지지 영역 A 안에 있어도, 이동 속도를 고려했을 때 곧 A를 벗어날 것으로 예상되면 발딛기를 시작하는 방식을 채택한다.

현재 COM이 A 밖으로 나간 뒤에만 반응하는 방식으로 제한하지 않는다. 위치·속도 기반으로 **0.3초** 뒤의 COM을 예측하고, 반대쪽 지지발의 **실제 물리 지면 접촉**을 확인해 새 발딛기의 시작을 허용한다. 바닥 레이 성공만으로 지지 중이라고 판단하지 않는다.

### 시작·진행·종료 규칙

| 항목 | 확정한 규칙 |
| --- | --- |
| 시작 판단용 시간 | `T_start = 0.3초`, 전후좌우 공통 |
| 지지발 판정 | PhysX의 실제 물리 지면 접촉 사용 |
| 움직일 발 | 시작 시 파란 발을 저장하고 해당 발딛기 종료까지 유지 |
| 진행 중 | 새 발딛기를 중복 시작하지 않고, 저장된 발의 착지 목표만 갱신 |
| 정상 종료 | 착지를 확인한 뒤 최신 상태로 다음 발딛기 필요성을 다시 판단 |
| 실제 COM의 B 이탈 | 진행 중인 절차적 발 보정 중단 + 골반 보조 지지 해제 |

Idle에서 새 발딛기를 시작하려면 예측 COM의 A 이탈, 사용 가능한 발 후보와 착지 목표, 반대 발의 실제 지면 접촉을 확인한다. 이미 발딛는 중이거나 B 이탈에 따른 해제 상태이면 새로 시작하지 않는다. 시작 전 유효한 파란 후보가 없으면 임의로 다른 발을 정하지 않고 시작을 보류한다.

시작 이후에는 A 밖으로 나가 실시간 후보 표시가 사라져도 저장한 발을 계속 사용한다. 원시 거리 후보가 바뀌어도 진행 중인 발을 교체하지 않는다. B 이탈에 따른 중단은 정상 착지 처리나 다음 발딛기 판단보다 우선한다.

착지는 실제 지면 접촉을 기반으로 확인한다. 시작할 때 이미 땅에 닿아 있는 발을 즉시 착지 완료로 판정하지 않도록, 발 이동을 연결할 때 이륙 후 재접촉을 구분한다. 세부 접촉 안정화 수치는 구현 검토 사항이며 여기서 임의로 정하지 않는다.

### 착지 목표는 COM 예측과 발 간격으로 계산

실제 COM 위치와 수평 속도로 미래 COM 위치를 예측하고, 기준 균형 자세의 발 간격 보정을 더해 착지 후보를 만든다. 발 간격, 제한 방식, 발을 든 뒤 목표 갱신은 레퍼런스의 일반 균형 발딛기 방식을 첫 버전에 채택한다.

착지 예측 시간 `T_land`의 첫 검증 초깃값은 **0.3초**로 한다. 전후좌우에 같은 값을 사용하고, 레퍼런스처럼 전방·후방 시간을 따로 두어 보간하지 않는다. 실제 회복 성능을 검증해 확정한 수치는 아니다.

| 항목 | 채택한 첫 설정 |
| --- | --- |
| 발 간격 | 기준 균형 자세의 양발 평균 대비 각 발 수평 오프셋 × 0.8 |
| 최대 보폭 | 반대쪽 지지발부터 착지 후보까지 최대 2m |
| 발 교차 억제 | 기본 OFF. 켤 경우 금지 경계면 오프셋 0.1m |
| 다리 길이 기반 도달 범위 제한 | 후보 생성 단계에는 별도 추가하지 않음 |
| 지면 높이 | 반대쪽 지지발 위치와 접촉 법선으로 만든 평면에 투영 |
| 발을 든 이후 | 최신 COM 위치·속도로 목표를 계속 재계산 |

이 채택으로 기존 초안의 별도 도달 범위 제한, 항상 켜진 교차 방지, 미래 후보 지면 조회는 첫 버전에서 제외한다. 필요하면 검증 결과에 근거해 별도 변경으로 제안한다. 2m와 0.1m는 첫 실험의 미터 단위 초깃값이며, 캐릭터 크기에 적합하다고 검증된 값은 아니다.

### 움직일 발의 기본 후보는 기존 파란 발

기존 `FootSupportCandidates.step`으로 표시하는 파란 발을 움직일 발의 기본 후보로 사용한다. 빨간 발은 반대쪽 지지 후보로 사용한다. 레퍼런스의 가장 긴 이동 거리 기준으로 후보 선택을 교체하지 않는다.

파란 발로 선택됐다는 사실은 실제 접촉 하중이나 발딛기 실행 가능성을 보장하지 않는다. 현재 후보는 COM이 A 내부이고 양발 투영 영역이 유효할 때만 존재한다. 따라서 시작 시 선택한 발을 별도로 저장하고, A 이탈이나 후보 소실로 진행 중인 발을 바꾸지 않는다. 진행 중 표시에는 저장된 제어 대상 발과 원시 거리 후보를 혼동하지 않도록 한다.

### 이동 중에는 기존 애니메이션 스윙의 착지를 보정

한 발이 지지하고 다른 발이 애니메이션에 따라 이동 중일 때, 한 발 지지라는 이유로 발딛기를 보류하거나 다른 발의 착지까지 기다리지 않는다. 애니메이션은 계속 진행하고, 이동 중인 발이 원래 착지하려던 위치를 COM 기반 착지 후보 쪽으로 보간해 궤적을 보정한다.

- Idle에서 새로 발을 드는 절차적 발딛기 시작과, 이미 진행 중인 걷기·달리기의 스윙 보정을 구분한다.
- 이동 중 보정은 현재 스윙 중인 발에 적용한다. 균형 보정 때문에 애니메이션 시간을 멈추거나 새 스윙으로 초기화하지 않는다.
- 애니메이션의 발 들기·이동·내리기 흐름을 활용하면서 착지점을 바꾼다. 현재 공중의 발 목표를 지면의 착지점에 곧바로 보간해 발 높이가 무너지는 방식과 구분한다.
- COM 기반 후보와 애니메이션의 원래 착지점 사이의 보간 비율, 스윙 진행에 따른 보정 적용 곡선, 접촉 후 보정 종료 방식은 추가로 정한다.
- 기존 COM 거리 기반 파란 발 후보가 실제 애니메이션 스윙발과 항상 같지는 않으므로, 이동 모드에서는 스윙발 판정과 파란 발 표시를 어떻게 연결할지 설계한다. 이 사항은 Idle의 기존 후보 사용 방침과 구분한다.

이동 중에는 발을 새로 들 수 있는지에 대한 조건으로 이미 진행 중인 스윙 보정까지 막지 않는다. 실제 COM이 B를 벗어난 경우의 회복 한계 정책은 별도로 유지한다. 첫 검증은 Idle 더미부터 한다는 순서는 변경하지 않는다.

### 한 발 지지 중에도 충격을 받고, 실제 COM이 B를 벗어나면 넘어짐을 허용

충격 적용을 반대 발의 착지까지 지연하지 않는다. 달리기 등으로 한 발만 지지하는 중에도 충격은 그대로 물리 시뮬레이션에 반영한다.

실제 COM의 바닥 투영점이 유효한 B를 벗어나면 회복 한계를 넘은 것으로 취급하고, 기존 골반 보조 지지를 해제해 넘어짐을 허용하는 방침을 채택한다. 예측 COM의 A 이탈은 발딛기 필요성 판단이고, 실제 COM의 B 이탈은 보조 지지 해제 판단이므로 구분한다. 경계 포함 여부는 기존 규칙대로 B 경계에서 지지 계수가 0이 된다.

B 이탈 시 진행 중인 절차적 발 보정을 중단하고 골반 보조 지지를 해제한다. 계산해 둔 착지 후보가 있어도 이후 제어에 계속 적용하지 않는다. 기존 골반 지지 해제 유지 동작과 연결해 COM이 다시 B 안으로 들어왔다는 이유만으로 발 보정을 자동 재개하지 않는다.

이 처리는 강제로 넘어지는 자세를 지정하거나, 일반 관절 PD까지 자동으로 끄는 처리가 아니다. 회복용 발 보정과 골반 보조 지지를 끄고 물리적으로 넘어지도록 두는 의미이며, 실제 넘어짐 여부는 접촉·관성·관절 구동에 따른 결과다.

한 발 지지 상태와 양발이 공중에 있는 상태를 구분한다. 일반 달리기의 공중 구간에서 유효한 A/B가 없어지는 현상을 실제 COM의 B 이탈로 간주하지 않도록, 이동 애니메이션 연동 단계에서 별도 정책을 정한다. 기존 자동 지지의 `Invalid → NoSupport` 해제 유지 규칙을 그대로 달리기에 적용해도 된다고 가정하지 않는다.

## 3. 현재 구현에서 활용할 기반

- 실제 물리 바디의 질량과 질량중심으로 계산하는 전체 COM.
- 발바닥의 지면 투영점으로 구성하는 지지 영역 A와 완충 영역 B.
- A/B에 따른 골반 보조 지지 계수.
- COM과 각 발 투영 중심의 수평 거리로 정하는 지지발·디딜발 관측용 후보.

현재 A는 레이 투영으로 얻은 영역이며, 실제 접촉 하중을 확인한 지지 영역과는 구분한다. 현재 발 후보는 A 내부에서만 계산되고 디버그 표시에 사용된다. 미래 착지 위치나 발딛기 시작 명령은 아직 생성하지 않는다. 이번 계획의 실제 접촉 도입은 시작 허용과 착지 확인을 위한 것이며, A/B의 생성 방식을 접촉점 기반으로 교체한다는 뜻은 아니다.

## 4. 구현 세부 및 후속 단계

첫 Idle 실험의 주요 동작 규칙은 위와 같이 확정한다. 다음 사항은 구현 검토와 후속 단계에서 구체화하며, 이동 모드의 모든 조건을 Idle 구현 전에 확정할 필요는 없다.

- 실제 지면 접촉을 수집하는 PhysX 경로, 자기 충돌·트리거·벽 접촉 제외, 접촉 안정화 및 이륙·재접촉 구분.
- 기준 균형 자세와 지지 좌표계 방향을 기존 PARS 데이터에 연결하는 방법.
- 후보 계산·발 궤적·IK 목표·실제 발의 디버그 출력, 각 단계 검증과 실제 착지·균형 회복의 통합 검증.
- 발 들기 높이는 수평 이동 거리의 25%, 상한은 기준 자세의 종아리 길이로 합의했다. 내리기 방식·진행도, 발 방향 목표, 무릎 굽힘 방향, 지지 다리 목표 유지 및 IK 종료 처리를 구체화한다.
- 고정 물리 스텝에서 B 이탈 중단을 우선 처리하고, 리셋·PA 재생성 때 저장된 발과 접촉 이력을 초기화하는 연결.
- 충격 조건, 계측 항목, 시뮬레이션 A/B 재현 조건 및 비교 보고서의 구체화.
- 이후 이동 모드: 스윙 구간·원래 착지점 판정, COM 목표와의 보간 비율 및 궤적 적용 곡선, 실제 스윙발과 파란 표시 연결, 달리기 공중 구간 및 이동 지면 처리.

필터나 추가 제한이 필요하면 변경 이유와 영향을 드러내고 검토한다. 미정인 세부 수치를 검증된 값처럼 기록하지 않는다.

## 5. 첫 COM 예측 모델

계획의 기본안은 실제 COM 위치와 수평 속도를 이용한 등속 예측이다. 아래 식은 예측 시간 동안 현재 속도가 유지된다는 근사이며, 실제 미래 COM 위치를 보장하지 않는다.

```text
T_start = 0.3초 (전후좌우 공통)
시작 판단용 예측 COM_XZ = 현재 COM_XZ + COM 속도_XZ × T_start
COM 속도 = Σ(바디 질량 × 바디 질량중심의 실제 선속도) / 전체 질량
```

정지한 바닥의 Idle 실험에서는 월드 수평 속도를 사용할 수 있다. 애니메이션 목표 속도나 골반 하나의 속도로 전체 COM 속도를 대신하지 않는다.

첫 예측은 위치와 속도를 사용한다. 충돌 순간의 큰 가속도가 예측 시간 동안 지속된다고 가정하면 과도하게 예측할 수 있으므로, 가속도 항이 필요한지는 이후 결과로 판단한다. 시작 판단용 `T_start`와 착지 목표용 `T_land`는 모두 방향 공통 0.3초로 시작한다.

## 6. 착지 목표 위치 계산 계획

기본 흐름은 COM 예측 → 기준 자세의 발 간격 반영 → 지지 평면 투영 → 최대 보폭 및 선택적 금지 영역 제한 → 착지 후보 출력이다. 레퍼런스 방식 채택에 따라 다음 규칙으로 계획한다. 기존 PARS의 좌표 데이터와 연결하는 세부 설계는 남아 있다.

### 6.1 입력과 계산 시점

- 고정 물리 스텝에서 읽은 실제 COM 위치와 질량 가중 평균 선속도.
- 좌우 발의 실제 발바닥 기준점과 지지 상태.
- 기준 균형 자세의 발 오프셋과 지지 좌표계 방향. Idle 더미에서는 기준 Idle 자세를 연결하는 안을 사용한다.
- 착지 예측 시간 `T_land`, 최대 보폭, 발 간격 비율, 교차 억제 설정.
- 반대쪽 지지발 위치와 접촉 법선. 첫 평지 실험에서는 위쪽 방향을 평면 법선으로 사용할 수 있다.

예측에 사용하는 COM·속도·현재 발 위치는 같은 물리 상태를 기준으로 읽는다. 정지한 바닥의 Idle 더미부터 검증하며, 렌더 프레임 간격으로 예측을 갱신하지 않는다.

### 6.2 목표점의 의미

착지 목표는 발 바디 질량중심이나 발목 본 위치가 아니라, 지면에 놓을 발바닥 기준점의 월드 위치로 정의하는 안을 사용한다. 기존 `FootSupport`의 발바닥 설정과 바디 로컬 변환을 활용한다.

IK·물리 목표로 변환할 때에는 발바닥 기준점과 발 바디·본 사이의 오프셋을 반영해야 한다. PA 수정으로 오프셋이 달라져도 발 바디 중심을 지면에 놓는 오류가 생기지 않도록 한다. 실제 발 이동과 IK는 후보 계산에 이어 같은 구현 범위에서 연결한다.

### 6.3 COM으로부터 양발의 원시 후보 생성

```text
T_land = 0.3초 (전후좌우 공통 초깃값)
착지 시점의 예측 COM_XZ = 현재 COM_XZ + COM 속도_XZ × T_land
왼발 원시 목표_XZ = 착지 시점의 예측 COM_XZ + 왼발 간격 오프셋_XZ
오른발 원시 목표_XZ = 착지 시점의 예측 COM_XZ + 오른발 간격 오프셋_XZ
```

- `T_start`는 발딛기가 필요한지 판단하는 예측 시간이고, `T_land`는 발을 놓을 시점의 몸 위치를 예상하는 시간이다. 첫 설정은 둘 다 전후좌우 공통 0.3초다.
- `T_land`가 실제 착지 시간을 결정하거나 보장하지는 않는다. 이후 발 이동 제어의 소요 시간과 맞춰 검증해야 한다.
- 발 간격 오프셋은 기준 균형 자세에서 양발 평균 대비 각 발의 오프셋을 구하고, 지지 좌표계 방향으로 변환한 수평 성분에 0.8을 곱한다. 기준 자세가 앞뒤로 벌어져 있으면 그 성분도 반영한다. 충격으로 현재 발이 벌어진 정도를 그대로 기준 간격으로 갱신하지 않는다.
- 지지 좌표계를 PARS에서 구성하는 세부 방식은 추가로 정한다. 레퍼런스의 발 간격 변환을 골반의 순간 회전에 그대로 대입하는 것으로 간주하지 않는다.
- 예측 COM에 양발을 모두 겹쳐 놓지 않는다. 각 발의 후보를 먼저 계산하고, 움직일 발의 선택은 후보의 유효성 및 지지 가능성과 연결한다.

### 6.4 보폭·도달 범위·교차 제한

- 지면 평면에 투영한 후보를 반대쪽 지지발 기준 반경 2m 이내로 제한한다. 움직일 발의 시작점부터 재는 이동 거리 제한과 구분한다.

- 첫 후보 생성에는 다리 길이로 계산한 별도 도달 범위 제한이나 무릎 여유값을 추가하지 않는다.
- 임의의 추가 금지 영역은 첫 평지 실험에서 설정하지 않는다.

따라서 후보가 생성됐다는 사실만으로 실제 다리가 닿거나, 발이 교차하지 않거나, 장애물 없는 경로로 이동할 수 있다고 보장하지 않는다. 실제 IK·발 이동을 연결할 때 발생하는 한계는 계측해 별도로 판단한다.

### 6.5 지면 높이와 유효성

- 반대쪽 지지발 위치를 지나는 수평 평면에 후보를 먼저 투영한 뒤, 지지발 접촉 법선을 사용하는 지면 평면에 투영한다. 첫 평지 실험에서는 두 평면이 같다.
- COM의 Y 좌표를 그대로 발 목표 높이로 사용하지 않는다.
- 후보 위치로 새 레이를 쏘아 지면을 탐색하는 처리는 첫 버전에 추가하지 않는다. 단차·구멍·장애물 또는 후보 발바닥 전체의 지지 가능성은 이 방식으로 확인되지 않는다.
- 지지 평면을 구성할 유효한 입력이 없으면 후보 계산 불가로 표시한다. 새 발딛기는 반대 발의 실제 지면 접촉이 있을 때만 허용한다. 진행 중 입력 상실과 달리기의 공중 구간 연결은 구현·후속 검토 항목이다.

### 6.6 출력과 목표 갱신

양발 각각에 대해 원시 목표, 제약 적용 후 목표, 지면 법선, 예상 이동 거리, 유효 여부와 실패 사유를 출력하도록 계획한다. 이 결과를 발 선택 및 이후 발 이동 제어에 전달한다.

후보 계산 자체가 발딛기 시작을 뜻하지는 않는다. 시작 조건을 만족하면 현재 파란 발을 저장하고 그 발의 착지 후보를 사용한다. 시작 전 후보나 목표가 계산 불가이면 새 발딛기를 시작하지 않는다. 진행 중에는 실시간 파란 후보가 사라지거나 바뀌어도 저장한 발의 목표만 갱신한다.

일반 균형 발딛기에서는 발을 들기 전과 든 후 모두 고정 물리 스텝마다 최신 COM 위치·속도로 목표를 재계산한다. 처음 정한 월드 목표를 고정하지 않으며, 후보 위치 변화에 별도 속도 제한을 추가하지 않는다.

발 이동을 연결할 때에는 시작 기준과 초기 보폭을 유지해 진행도를 계산한다. 목표가 바뀌었다고 발딛기 상태나 경과 시간을 매번 초기화하지 않는다. 레퍼런스의 시작 기준은 반대 발에 대한 상대 위치이므로, 월드에 고정된 시작점과 구분한다.

진행 중 중복 시작을 금지하고, 실제 착지를 확인한 뒤 다음 발딛기 필요성을 재평가한다. 실제 COM의 B 이탈 시에는 정상 착지까지 기다리지 않고 진행 중 발 보정을 중단한다.

## 7. 발 이동 궤적·다리 IK·물리 구동 연결

### 7.1 전체 처리 흐름

```text
실제 물리 상태·접촉 샘플링
→ B 이탈 및 발딛기 상태 판단
→ 움직일 발 선택·저장과 착지 후보 계산
→ 애니메이션 기본 목표 자세 평가
→ 이번 스텝의 발 위치·방향 목표 생성
→ 다리 IK로 본 목표 자세 보정
→ 기존 UpdateDriveTargets로 바디·관절 목표와 목표 속도 계산
→ UpdateArticulationDrives 및 PhysX 시뮬레이션
→ 다음 물리 스텝에서 실제 접촉·이륙·착지 확인
```

후보 계산만 완료한 상태를 실제 발딛기 구현 완료로 취급하지 않는다. 함수별 개발은 나눌 수 있으나, 첫 통합 검증은 발을 실제로 들고 내려놓는 동작까지 포함한다.

### 7.2 Idle 발 이동과 이동 애니메이션 보정

Idle에는 이미 진행 중인 보행 스윙이 없으므로, 선택한 발의 현재 위치에서 발을 들고 착지 목표를 향해 이동한 뒤 내려놓는 궤적을 생성한다. 착지점만 IK에 넣어 지면을 따라 발을 끌게 하지 않는다.

걷기·달리기 단계에서는 합의한 대로 기존 애니메이션 스윙의 착지 위치와 궤적을 보정한다. 두 방식은 착지 후보 계산과 다리 IK를 공유할 수 있게 구성한다.

### 7.2.1 들기 높이: 수평 거리 비례 + 상한

고정된 들기 높이 대신 수평 이동 거리에 비례하는 기본 목표 높이를 사용하고, 최대 높이로 제한한다. 멀리 딛는 경우 더 높게 들도록 하되 상한 이상으로 높이지 않는 방식을 채택한다.

```text
D = 선택한 발의 시작 발바닥 위치부터 최종 착지 후보까지의 XZ 거리
k = 0.25
H_max = 선택한 다리의 기준 자세에서 무릎~발목 사이 길이
기본 들기 높이 H = min(k × D, H_max)
진행 중 상승 목표 성분 = H × (1 − 진행도)
```

- 거리 대비 높이 비율 `k`의 초깃값은 **0.25**로 채택한다. `H_max`는 선택한 다리의 기준 자세에서 무릎~발목 사이 길이를 사용한다. 현재 자세의 수직 투영 길이를 매번 사용해 상한이 바뀌는 방식과 구분한다.
- `D`는 움직일 발 자체가 이동할 수평 거리다. 반대 지지발 기준 최대 보폭 2m를 검사하는 거리와 구분한다.
- 시작 시 `D`와 `H`를 저장해 한 번의 발딛기 동안 사용한다. COM 변화로 착지 후보가 갱신돼도 초기 들기 높이를 매번 재설정하지 않고 진행도에 따라 낮춘다.
- 남은 거리를 매번 `D`로 대입한 뒤 진행도 감소를 또 곱해 높이를 이중으로 줄이지 않는다.
- 레퍼런스의 이륙 후 추가 `stepLength / maxStepLength` 높이 축소를 그대로 중복 적용하지 않는 안을 사용한다. 이미 `k × D`에서 짧은 보폭의 높이를 낮추기 때문이다.
- 상한은 궤적 생성에 사용하는 목표 높이에 대한 제한이며, 실제 물리 발의 최대 높이를 강제로 고정하는 제한은 아니다.

A~B 정규화 계수로 들기 높이나 발 이동 진행도를 대신하는 안은 사용자의 지시에 따라 폐기한다. 들기 높이는 발 자체의 수평 이동 거리로 정하고, 발 이동 진행도와 COM의 지지 영역 판정은 분리한다.

채택한 초깃값에서는 수평 이동 거리 0.4m이면 기본 목표 높이 0.1m, 0.8m이면 0.2m가 되며, 종아리 길이에 해당하는 상한을 넘지 않는다. 사용자와 합의한 설계값이며, 시뮬레이션 검증은 아직 하지 않았다. 실제 발 끌림·이륙과 착지 시간을 확인해 조절할 수 있도록 설정값으로 둔다.

내려놓기 속도, 진행도 계산 및 궤적 함수의 나머지 세부값은 추가 설계 항목이다. 예측 시간 0.3초를 발 이동 완료 시간으로 자동 대입하지 않는다. 진행 중 착지 후보가 갱신되어도 이륙·착지 상태와 시작 기준을 초기화하지 않는다.

### 7.3 IK의 역할과 적용 위치

다리에는 표준 **Two-Bone IK**를 채택한다. 고관절·무릎·발목의 세 관절과 허벅지·종아리의 두 구간을 사용해 목표 발목 위치에 맞는 다리 목표 회전을 계산한다. 발 자체의 목표 방향은 별도의 발 회전 목표로 반영한다.

```text
고관절(Root) ── 허벅지 ── 무릎(Mid) ── 종아리 ── 발목(Tip)
                                      ↑
                              무릎 굽힘 방향 Hint
```

연결 순서는 다음과 같다.

1. 해당 스텝의 발바닥 목표 위치·방향을 얻는다.
2. 발바닥 기준점, PA 바디 로컬 변환, 발목 본 사이의 오프셋을 반영해 발목의 목표 위치·회전으로 변환한다. 목표 발 회전이 바뀌면 위치 오프셋도 그 회전에 맞춰 변환한다.
3. 고관절 위치, 허벅지·종아리 길이, 목표 발목 위치, 무릎 Hint를 같은 좌표계에 준비한다.
4. 두 뼈와 고관절~목표 발목 거리로 구성한 삼각형을 코사인 법칙으로 풀고, Hint가 정하는 평면에서 무릎 위치와 허벅지·종아리의 목표 회전을 계산한다.
5. 발 본의 목표 방향을 적용하고 관련 자식 본 목표를 일관되게 갱신한다.
6. 최종 본 목표를 기존 바디·관절 목표 변환과 PD 구동에 전달한다.

무릎 Hint는 기본 애니메이션의 굽힘 방향을 참고한다. 다리가 거의 일직선이라 굽힘 방향이 불안정할 때는 이전 유효 방향 또는 기준 자세 방향을 사용하는 처리를 포함한다. 실제 물리 골반과 애니메이션 목표 골반의 차이를 고려해 IK의 기준 위치와 목표 좌표계를 일치시킨다.

뼈 길이를 늘려 목표에 맞추지 않는다. 도달할 수 없는 목표와 거의 완전히 펴지거나 접힌 자세에서는 계산용 거리를 두 뼈의 기하학적 도달 구간 안으로 제한해 수치 오류를 방지하고, 원래 요청 목표와 IK 결과 사이의 오차를 기록한다. 이는 착지 후보 자체의 최대 보폭 규칙을 바꾸거나 원래 목표에 도달했다고 보고하는 처리가 아니다.

기본 Two-Bone IK는 PA의 모든 회전축 제한을 자동으로 푸는 알고리즘이 아니다. IK가 만든 자세를 기존 관절 목표·제한에 변환한 뒤의 결과까지 확인하고, 제한으로 생긴 추종 불가능성과 오차를 구분한다. 반대쪽 지지 다리는 접촉을 유지하는 데 필요한 목표를 함께 검토하며, 리지드바디를 월드에 강제로 고정하는 방식으로 대체하지 않는다.

현재 코드에서는 `SkeletalMeshComponent::FixedTickComponent()`의 `EvaluateAnimationPhysicsPose()` 결과와 `Ragdoll::UpdateDriveTargets()` 호출 사이에 최종 본 목표 보정을 연결하는 안을 사용한다. 관련 자식 본과 발바닥·PA 오프셋도 일관되게 반영한다. 보정이 끝난 목표로 관절 상대 회전과 목표 각속도를 계산하도록 순서를 유지한다.

IK 결과는 물리 구동 목표다. 실제 바디 위치를 직접 덮어쓰거나 렌더링된 발만 옮겨서 착지한 것처럼 만들지 않는다. 실제 발 움직임은 기존 관절 PD와 접촉 풀이가 수행하므로, 목표 도달 여부를 실제 바디와 접촉으로 확인한다.

후보 생성의 최대 보폭 2m와 별도 도달 범위 제한 없음이라는 합의는 유지한다. IK가 도달할 수 없는 목표에서는 뼈 길이를 늘리거나 실제 발이 도달했다고 간주하지 않고 목표 오차를 기록한다. 후보 제한을 바꿀 필요가 확인되면 별도 변경으로 드러낸다.

개념 참고: [Unity Two Bone IK 공식 문서](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html). Root/Mid/Tip, Target, Hint 및 목표 회전의 역할을 참고하며, Unity 런타임 의존성을 추가하는 계획은 아니다.

### 7.4 착지·중단 및 검증

실제 착지를 확인하면 해당 발딛기를 종료하고 다음 필요성을 평가한다. 실제 COM의 B 이탈 시에는 궤적·IK를 통한 절차적 발 보정 출력을 중단하고 골반 보조 지지를 해제한다. 일반 관절 PD와 애니메이션을 자동으로 정지시키는 의미는 아니다.

통합 검증에서는 목표 궤적과 실제 발 궤적, 이륙·착지 시점, 발 끌림·미끄러짐, 무릎 방향, 지지발 접촉, 골반·COM 이동, B 이탈 시 중단을 확인한다. 궤적이 그려지거나 IK 자세가 생성됐다는 사실만으로 실제 착지·회복 성공을 보고하지 않는다.
