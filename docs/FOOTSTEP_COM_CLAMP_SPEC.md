# 발딛기 착지용 COM 예측 제한 명세

작성·수정일: 2026년 11월 16일

현재 구현은 사용자가 확인한 두 조건을 따른다. 원점은 현재 COM을 따라 이동하고, 금지 구간은 현재 COM에서 실제 지지발 사각형의 바깥 꼭짓점으로 향하는 두 레이 사이이다. 기존 고정 45° 방식과 해당 각도 조절 설정은 제거했다.

## 제한 대상과 입력

제한 대상은 **발 오프셋을 더하기 전의 착지용 COM 예측점**이다. 최종 발 착지점을 직접 제한하는 기능으로 바꾸지 않는다.

움직일 발을 평가할 때 그 반대쪽에서 실제 접지한 발을 지지발로 사용한다. 지지발 사각형은 FootSupport의 발바닥 설정과 현재 물리 발 자세로 만든 네 꼭짓점이다. 양발 전체의 Convex Hull이나 Idle 때 저장한 사각형을 대신 사용하지 않는다. 수평 판정에는 꼭짓점의 XZ 성분을 사용한다.

| 항목 | 현재 동작 |
| --- | --- |
| 원점 | 매 완료 물리 스텝의 현재 전신 COM 수평 위치 |
| 지지발 | 평가 중인 이동 발의 반대쪽 실제 접지 발 |
| 금지 영역 | COM에서 지지발 사각형을 감싸는 두 바깥 레이 사이의 부채꼴 |
| 레이 길이 | 사각형 앞에서 시작해 사각형 너머까지 연장 |
| 금지 폭 | 현재 COM, 발 크기와 실제 발 회전으로 계산 |
| 허용 영역 | 금지 부채꼴의 바깥, 두 경계 및 COM 원점 |
| `minimumStanceWidthRatio` | `0` |
| `preventCrossing` | `false` |
| 실제 COM·속도·충격량 | 보정을 위해 덮어쓰지 않음 |

## 사각형에서 경계 구하기

현재 COM을 원점으로 옮긴 사각형 꼭짓점의 수평 방향을 비교한다. 사각형 중심을 향하는 방향을 기준으로 각도를 펼치고, 가장 작은 각도와 가장 큰 각도의 꼭짓점을 고른다. 이 두 꼭짓점으로 향하는 단위 벡터가 경계 레이다. 이렇게 비교하면 월드 각도의 -180°/180° 경계나 캐릭터의 회전에 영향을 받지 않는다.

원점에서 사각형까지 거리, 사각형의 가로·세로 크기, 발 회전이 바뀌면 경계를 다시 구한다. 앞뒤·좌우에 대칭인 고정 부채꼴을 별도로 만들지 않는다.

```text
p_land_raw = c_xz + v_xz * T_land
region = BuildFootstepLandingRegion(c_xz, support_corners_xz, character_forward)
p_land_clamped = ClampLandingPrediction(region, p_land_raw, boundary_history)
p_foot_raw = p_land_clamped + stanceScale * o_foot_xz
```

`c_xz`와 `v_xz`는 현재 전신 COM의 수평 위치와 월드 속도, `T_land`는 착지 예측 시간 0.4초다. `support_corners_xz`는 반대쪽 지지발의 현재 네 꼭짓점, `o_foot_xz`는 해당 이동 발의 Idle 배치 오프셋이다. 캐릭터 앞 방향은 경계의 앞뒤 이름과 동률 선택에만 쓰며 금지 각도를 결정하지 않는다.

## 금지 구간 안의 예측점 보정

허용 영역의 예측점은 그대로 유지한다. 금지 구간 안의 점은 두 경계 반직선에 각각 직교 투영한 뒤 이동량이 작은 후보로 옮긴다.

```text
d = p_land_raw - region.origin
t_front = max(0, dot(d, region.frontRay))
t_back = max(0, dot(d, region.backRay))
q_front = region.origin + region.frontRay * t_front
q_back = region.origin + region.backRay * t_back
```

`frontRay`와 `backRay`는 실제 사각형 꼭짓점을 통과하는 수평 단위 벡터다. 두 투영 거리가 같으면 캐릭터 앞 방향 성분이 큰 경계를 처음 선택한다. 이후 진행 중인 같은 명령에서는 부채꼴 이등분선 근처에서 이전 경계 선택을 유지한다. 기본 유지 반각 5°는 경계 교번을 막는 설정이며, 금지 영역을 5°만큼 확장하지 않는다.

변위가 0이면 원점을 유지하고 경계를 새로 선택하지 않는다. 이력은 각 발의 진행 중인 명령에만 저장하며 명령 종료·중단·리셋·리비전 변경·시계 되감기·활성 모드 이탈·기능 끄기에서 정리한다.

## 지지 사각형이 없는 경우

반대 발이 접지하지 않았거나, 사각형이 없거나 유효하지 않으면 금지 각도를 임의로 만들지 않고 기존 착지 COM 예측을 유지한다.

COM이 지지발 사각형 안 또는 경계에 있으면 바깥 접선 두 개로 유일한 부채꼴을 정의할 수 없다. 이 경우 `containsCom`으로 구별하고 방향 제한을 적용하지 않는다. 발이 거의 옆으로 서서 수평 사각형이 퇴화한 경우도 기존 예측을 유지한다. 디버그에는 해당 사각형을 표시할 수 있지만 인위적인 45° 구간으로 대체하지 않는다.

## 시작 판정과 목표 잠금

시작 필요성은 기존 0.6초 보정 전 COM 예측으로 판단한다.

```text
p_start_raw = c_xz + v_xz * T_start
```

실제 COM의 A/B 영역 판정과 낙상 전환은 기존 물리 관측을 사용한다. 발 선택, 실제 이륙·접촉 판정, 지면 투영, 최대 보폭 1m, 발 이동 시간 0.1초, 관절 구동 설정도 유지한다.

목표를 갱신할 수 있는 동안에는 현재 COM과 지지 사각형으로 구간과 보정점을 다시 계산한다. 이동 진행률 75% 이후에는 기존 수평 착지 목표를 잠그며, 새 구간이나 표시용 예측 때문에 잠긴 발 목표를 움직이지 않는다.

## 인게임 표시

`더미 충격 테스트 → 발바닥 / 지면 투영 → 착지 COM 제한 구간 표시`에서 표시를 켜고 끈다. 기본은 켜짐이다. 표시 여부는 물리 상태나 제한 기능을 바꾸지 않는다.

플레이어의 발 상태와 발 디버그는 기본으로 꺼져 있으며 `캐릭터 애니메이션` 창의 각 버튼으로 켠다. 더미는 별도 표시 객체와 토글을 사용하므로 플레이어 표시 변경에 영향을 받지 않는다. 더미 발 상태와 발 디버그는 `더미 충격 테스트` 창에서 켜고 끈다.

화면 상단의 더미 접촉·경로 예측·일시정지 상태 문구는 `캐릭터 애니메이션` 창 첫 줄의 `상단 디버그 켜기/끄기` 버튼으로 표시를 전환한다. 기본은 꺼짐이다. 이 버튼은 접촉 검사나 일시정지 기능을 변경하지 않는다.

상단 표시의 기본 숨김과 버튼 위치는 [첫 화면 캡처](../.tools/top-debug-toggle-20261116/startup-ui.png)로 확인했다.

기본 표시 변경은 빌드와 실제 첫 화면으로 확인했다. [장면 캡처](../.tools/player-foot-debug-default-off-20261116/startup-scene.png)에서 플레이어 발 디버그가 숨겨지고 더미 표시가 유지되며, [UI 캡처](../.tools/player-foot-debug-default-off-20261116/startup-ui.png)에서 플레이어의 두 표시 버튼이 꺼진 상태와 발 디버그 설정 패널이 숨겨진 상태를 확인할 수 있다.

표시 원점은 렌더 시점에 읽은 현재 물리 COM의 XZ 위치다. 높이는 관측한 지면 높이에 맞춘다. 노란 COM 표시도 같은 현재 값을 사용한다. 사각형은 렌더 시점의 현재 물리 발 자세로 다시 배치한다. 제어용 스냅샷이나 발딛기 명령은 표시를 위해 갱신하지 않는다.

| 표시 | 의미 |
| --- | --- |
| 노란 원 | 현재 COM의 지면 투영 |
| 빨간 사각형 | 기준 지지발 사각형 |
| 회색 선 | COM에서 네 꼭짓점까지의 레이 |
| 빨간 빗금 | 지지발 사각형을 감싸는 두 레이 사이의 금지 부채꼴 |
| 초록 경계 | 허용되는 경계와 표시 원 |
| 주황 | 이등분선 근처의 경계 선택 유지 구간 |
| 파란 화살표 | 캐릭터 앞 방향 |
| 연보라 점 | 착지용 보정 전 COM 예측 |
| 연두 점·선 | 보정 후 COM 예측과 보정 연결선 |

발딛기 명령 전에는 양발 사각형의 구간을 미리 보여준다. 명령 중에는 반대쪽 실제 지지발의 구간만 그린다. 실제 제한 기능을 끄면 설정 구간을 회색으로 표시한다. 원의 반경은 사각형이 보이도록 잡는 표시 범위이며 레이의 물리적 끝이나 예측 거리 제한이 아니다.

## 설정과 재현

| 설정 | 기본값 |
| --- | --- |
| `landingComClampEnabled` | `true` |
| `landingComClampHysteresisDegrees` | `5°`, 유효 범위 `0° ≤ 값 < 90°` |

고정 허용 반각 설정과 `-landingcomangle` 옵션은 제거했다. 실제 계산된 금지 폭은 후보마다 읽기 전용 정보로 표시한다.

수학·상태 검사는 `PhysicsWorldTests.exe --footstep-only` 및 전체 PhysicsWorldTests에서 실행한다. 알려진 사각형 접선 투영, 발 전후로 연장되는 레이, 좌우 반전, 12개 캐릭터 방향, 평행 이동, 실제 발 회전·크기, COM 이동, 무효 사각형, COM의 사각형 내부·경계, 시작 예측, 기능 끄기, 경계 이력과 75% 목표 잠금을 확인한다.

실제 더미의 비교 실행은 `-landingcomclamp`만 0/1로 바꾸고 나머지 입력을 동일하게 둔다.

```text
ModelViewer.exe -physics 1 -bodyimpacttest <절대경로/report.txt> -kinematiccase 3 -landingcomclamp 1 -impactmass 2 -impactspeed 25 -impactsourcex 6.5 -impactsourcez -2.5
```

`report.txt.landing-com.csv`에 현재 COM, 원래·보정 예측, 지지발 번호, 구간 원점, 두 경계 방향, 계산된 금지 폭, 저장 목표, 실제 착지와 낙상·기상을 구분해 기록한다.

기존 45° 구현의 비교 기록은 `.tools/footstep-com-clamp-20261116`에 남아 있으며 현재 사각형 기반 구현의 검증 결과로 사용하지 않는다. 새 검증 산출물은 `.tools/footstep-com-foot-rays-20261116`에 저장한다.

## 사각형 기반 구현의 검증 결과

2026년 11월 16일 Debug x64 빌드에서 확인했다. 전체 PhysicsWorldTests, 발딛기 2,654개 검사, IK 289개 검사, 충돌 경로와 서 있기 검사가 통과했다. 작은 예측을 큰 월드 위치에 더할 때 경계 안으로 반올림되는 회귀도 검사하며, 경계의 수치 오차는 정규화한 각도 대신 미터 단위 거리로 처리한다.

25m/s 발사체의 질량 0.25kg·0.75kg·2kg·5kg, 좌우 원점 X=0.5/6.5, 기능 끄기/켜기 16회를 각각 900프레임 실행했다. 모두 유효한 물리 상태와 PhysX 오류 없음 검사를 통과하고 균형 복귀했다. 각 실행의 900프레임에서 실제 렌더 선으로부터 구한 원 중심이 현재 물리 COM을 따르는지도 검사했다. 별도 정지 Idle 900프레임 검사도 통과했다.

| 발사체 질량 | X=0.5의 발딛기 횟수, 끄기→켜기 | X=6.5의 발딛기 횟수, 끄기→켜기 |
| --- | --- | --- |
| 0.25kg | 0→0 | 0→0 |
| 0.75kg | 1→1 | 0→0 |
| 2kg | 1→1 | 5→5 |
| 5kg | 6→5 | 5→5 |

기록한 명령은 모두 실제 이륙과 착지가 확인됐다. 2kg, X=6.5 조건에서는 다리 접촉 프레임이 1→0, 명령별 최대 수평 착지 오차가 약 10.08cm→7.27cm로 줄었다. 이 입력군 외의 회복 성능까지 보장하는 수치는 아니다.

구간이 유효한 기록에서 원점과 측정 COM의 XZ 차이는 0이었다. 계산된 금지 폭은 입력·프레임에 따라 약 21.49°~179.84°로 달라졌다. 보정한 예측점의 금지 구간 내부 잔류는 수치 오차 허용 범위에서 0건이었다. [전체 집계](../.tools/footstep-com-foot-rays-20261116/comparison.json), [인게임 선 캡처](../.tools/footstep-com-foot-rays-20261116/idle-debug-lines-scene.png), [인게임 UI 캡처](../.tools/footstep-com-foot-rays-20261116/idle-debug-lines-ui.png)를 보관했다.

기존 `ModelViewer.exe`가 실행 중이어서 기본 출력 경로의 링크가 잠겼다. 검증 빌드는 같은 출력 폴더의 `ModelViewerFootRays.exe`로 생성했다. 현재 실행 중인 이전 프로그램에는 변경 사항이 실시간으로 적용되지 않는다. 검증 빌드를 실행하면 현재 사각형 기반 동작을 확인할 수 있다.
